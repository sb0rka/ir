# Добавление находок без вложенных событий

В панели добавления контекста расследования флажок **«Добавлять вложенные
события»** управляет раскрытием инцидентов, корреляций и атак. Он применяется
как к массовому добавлению, так и к добавлению из строки или карточки.
По умолчанию флажок включён для совместимости с прежним поведением.

API `POST /investigations/{investigation_id}/context` и добавление контекста
гипотезы принимают необязательный `resolve` в `ContextSelection`:

- `true` или отсутствие параметра: прежнее раскрытие находок;
- `false`: сохраняются только выбранные находки и их исходные метаданные;
  вложенные находки, сессии, события и отдельные сущности не добавляются;
- явно переданные `sessions`, `events`, `entities` обрабатываются как прежде,
  в том числе в смешанном запросе с `resolve: false`.

IR передаёт параметр в Gateway `POST /api/v1/context/resolve`. Адаптеры
MaxPatrol и PT NAD загружают корневую запись, но пропускают запросы вложенного
контекста. Проверки источника, идентификатора, временного интервала, project
scope и доступа к источнику сохраняются. Отсутствующий корневой объект
не заменяется пустой карточкой.

Статус `complete` при `resolve: false` означает полноту **запрошенной корневой
записи**, а не загрузку всех её вложенных событий. Метаданные карточки могут
содержать ссылки на участников или сессии; это не добавляет их в граф.
Уже импортированный контекст не удаляется. Для последующего раскрытия можно
повторить запрос с `resolve: true`.

Флаг не меняет группировку событий и не требует изменения схемы БД.
