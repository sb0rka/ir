# Правила разработки

Читается перед первой правкой — и человеком, и агентом.

## Устройство

Спека в `api/` — источник правды. Из неё генерируются Go-типы с серверными
интерфейсами и TypeScript-типы с клиентом; руками они не правятся. Как
устроена раскладка спеки — в [api/README.md](api/README.md).

Слои строгие: `transport` → `server` → `store` → `domain/model`. Единственная
дверь к базе — интерфейс `store.Database`; новый запрос это метод интерфейса
плюс реализация с SQL инлайном в `psql.go`. Ошибки типизированные, транспорт
разворачивает их в конверт `{"error": {"code", "message", "details?"}}`.

Общее с платформой не переписывается: конфиг, логгер, пул Postgres и личность
из токена берутся из `github.com/sb0rka/sb0rka/packages/core`. Своим заводится
только то, чего у соседних сервисов нет, и с пометкой, когда оно переедет
в core.

## Добавили ручку в спеку

```bash
task gen      # спека, Go-контракт, заготовки хендлеров, TypeScript
task check    # то же самое плюс проверка, что сгенерированное не разошлось
```

1. URL и операции — в `api/paths/<домен>.yaml`, секция `paths`.
2. Схемы запроса и ответа — там же, в `components.schemas` этого файла.
3. Каждому полю — `description` на английском: описания уезжают
   в сгенерированный Go, в `.d.ts` и в Redoc, читает их не только автор.
4. В `api/shared/` схема переезжает, только когда понадобилась второму домену.
5. Повторяющиеся параметры и ответы не инлайнить — брать из `shared/`.
6. `task gen` и коммит сгенерированного вместе со спекой.

## Добавили домен

Новая ручка внутри существующего домена — это всё, что выше. Новый **домен**
стоит трёх шагов, которые генератор не сделает:

1. Файл начинается с шапки существующего: `openapi`, `info`, `servers`,
   `security`. Без `servers`/`security` ручки уедут в бандл без авторизации.
2. Тег — в `api/openapi.yaml`, иначе `lint` ругается на неописанный.
3. Пакет — в `API` и в `registerDomains`
   в `apps/investigations/internal/transport/router.go`. Забыть это компилятор
   не поможет: незарегистрированный домен молча отдаёт 404.

Удалили домен — `task gen` уберёт за ним сам (шаг `gen-prune`). Переименовали
`operationId` — старый метод в `internal/server/<домен>.go` надо снести руками:
`impl` только дописывает, и сборка ляжет на несуществующем типе.

## Тенант проверяется в каждой ручке

Часть путей адресуется глобально по id: `/entities/{id}`, `/events/{id}`.
В таком запросе расследования нет, а значит база не подстрахует — в отличие
от вложенных путей, где `investigation_id` приходит параметром и работают
составные внешние ключи.

Отсюда правило без исключений: **любая выборка по id фильтруется по
`project_id` из контекста**, а не проверяется после чтения. `project_id` —
первый параметр каждого метода стора, работающего по id: пропустить его
не даст сигнатура.

Отсутствие записи и запись в чужом тенанте отвечают одинаково — `404`. `403`
означал бы «такая запись есть, но не ваша», то есть подтверждал бы
существование чужих данных.

## Что не делается

- Не пишутся свои обёртки над тем, что уже есть в `packages/core`.
- Не правится сгенерированный код: правится спека.
- Не удаляется то, что проверили и исключили: `reject` с причиной идёт
  в отчёт, `delete` не оставляет следов. Это разные операции.
- Не заводятся таблицы и колонки под функциональность, которой ещё нет:
  схема без кода — мёртвый вес.

## Комментарии в коде

Комментарий объясняет «почему», а не «что». Пишется, когда фиксируется
неочевидное решение, причуда внешней зависимости или инвариант, который
из кода не читается. Пересказ имени функции — не комментарий.

## Коммиты

Conventional commits. Сообщение про «почему», а не про «что» — что видно
из diff.
