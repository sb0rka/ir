Обновлять при изменении контракта.

## Задачи сценария

| Задача | Как закрыта | Статус |
|---|---|---|
| Реконструкция цепочки атаки | Связи `subevent_of` и `followed_by` между событиями-узлами; таймлайн от точки входа | ✅ |
| Оценка распространения индикатора | `importIocs` с `retro_search=true`; `getEntityCard.occurrences` | ✅ |
| Триаж сработок | `listAlerts` — лента без персиста, из сработки заводится кейс | ✅ |

## Нефункциональные

| Пункт | Как закрыт |
|---|---|
| Аутентификация и авторизация | Ed25519 JWT платформы, проверка публичным ключом; роли из `role_bindings`, deny-by-default |
| Контроль передачи данных наружу | `sends_data_externally` у расширений, `external_call` в аудите, allowlist |
| Секреты | Только `secret_ref`, значения наружу не отдаются и в логи не пишутся |
| Воспроизводимость | `snapshot` в отчёте, `dedup_key` у событий, идемпотентность рёбер |
| Метрика сокращения шагов | `getInvestigationMetrics` — счётчики из журнала действий |
| Устойчивость к недоступности источника | `502 source_unavailable`, поле `partial` в результатах поиска, `getHealth` |

## Осознанно вне v0.1

| Что | Почему |
|---|---|
| Внутренний MCP-контур агента | Отдельная спека: другой контур авторизации (scoped-токен вместо пользовательского JWT), не публичный API |
| CRUD источников и расширений | На стенде конфигурируются миграцией; ручки чтения есть |
| Довешивание оснований к существующему ребру | `updateEdge` меняет только статус; основания задаются при создании |
| Батч-ревизия вердиктов под-расследований | По одному через `updateInvestigation`; батч есть только для рёбер |
| Подсказки следующих шагов (5.9) | Опционально по ТЗ |
