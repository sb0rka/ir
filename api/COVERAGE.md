# Покрытие требований ТЗ

Сверка спеки против функциональных требований и задач ТЗ Техлаб 2026.
Обновлять при изменении контракта.

Текущий объём: 20 путей, 32 операции, 43 схемы, 5 доменов.

Контракт намеренно урезан до ядра: граф, сущности, события, расследования.
Всё, что помечено «вне v0.1», не выброшено из продукта — просто ещё не описано
в контракте, чтобы спека не обещала того, чего нет.

## Задачи сценария

| Задача | Как закрыта | Статус |
|---|---|---|
| Реконструкция цепочки атаки | `createNode` выносит событие с таймлайна на граф, `createEdge` связывает через `subevent_of` / `followed_by` | ✅ |
| Оценка распространения индикатора | `getEntityCard.occurrences` — где ещё в тенанте встречается тот же ключ | 🟡 без ретро-поиска по IOC |
| Триаж сработок | Кейс заводится через `createInvestigation`; ленты сработок вне кейса нет | 🟡 |

## Нефункциональные

| Пункт | Как закрыт |
|---|---|
| Аутентификация и авторизация | Ed25519 JWT платформы, проверка публичным ключом; роли из `role_bindings`, deny-by-default |
| Изоляция тенантов | `project_id` из токена, не из тела; составные FK держат «улика того же кейса» на уровне БД |
| Секреты | Только `secret_ref`, значения наружу не отдаются и в логи не пишутся |
| Воспроизводимость | Идемпотентность затяжки событий и рёбер; `source_ref` до исходной записи у заказчика |
| Устойчивость к недоступности источника | `502 source_unavailable` на `attachEvents` — расследование при этом цело |

## Осознанно вне v0.1

| Что | Почему |
|---|---|
| Внутренний MCP-контур агента | Отдельная спека: другой контур авторизации (scoped-токен вместо пользовательского JWT), не публичный API |
| Артефакты и обогащение | Внешние вызовы — отдельный контур контроля передачи данных наружу, делаем после ядра |
| Отчёты и пакет реагирования | Производное от графа: пока граф не устоялся, формат отчёта фиксировать рано |
| Админка: источники, правила, роли, аудит, метрики | На стенде конфигурируется миграцией; API управления не защищает продукт |
| Сквозной поиск вне расследования и лента сработок | Триаж-контур целиком; работа с графом от него не зависит |
| Батч-ревизия вердиктов под-расследований | По одному через `updateInvestigation`; батч есть только для рёбер |
| Интеграция с SOM: агентские сессии, задачи по узлам | Связывать будем после того, как граф заработает сам по себе |
