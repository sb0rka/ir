# OpenAPI Investigations API

Источник правды контракта. Из спеки генерируются Go-типы с серверными
интерфейсами и TypeScript-типы с клиентом — руками они не правятся.

```
api/
├── openapi.yaml        только шапка: info, servers, security, tags, securitySchemes
├── shared/             ТОЛЬКО переиспользуемое между доменами
│   ├── enums.yaml      Severity, Origin, NodeType, EdgeStatus
│   ├── errors.yaml     ErrorResponse
│   ├── parameters.yaml id ресурсов, limit, cursor
│   └── responses.yaml  типовые 401/403/404/409/422/502
└── paths/              домен = файл: URL, ручки и их локальные схемы вместе
    ├── investigations.yaml дерево расследований
    ├── events.yaml         затяжка улик, таймлайн
    ├── entities.yaml       карточка сущности
    ├── graph.yaml          граф, узлы, рёбра, батч-ревизия
    └── reference.yaml      словари: типы сущностей, связей, источники
```

Пять доменов, тридцать операций — полный CRUD по расследованиям, уликам,
сущностям и графу, и ничего сверх этого. Триаж, артефакты, отчёты, админка,
интеграция с SOM добавляются отдельными файлами в `paths/`, когда до них
дойдёт очередь.

## Карта экранов

Чем закрывается каждый экран MVP — чтобы фронт не искал ручку по спеке.

| Экран | Ручки |
|---|---|
| Загрузка приложения | `getReference` — иконки типов, подписи связей, список источников; кэшируется на сессию |
| Список расследований | `listInvestigations` (фильтры `status`, `severity`, `q`, keyset-пагинация) |
| Создать кейс или гипотезу | `createInvestigation`; `parent_id` пустой — корень, задан — гипотеза |
| Карточка кейса | `getInvestigation` — счётчики в шапке; `counters.proposed_edges` — бейдж очереди ревизии |
| Дерево гипотез | `getInvestigationTree` — плоский пре-ордер с `depth`, дерево собирается за один проход |
| Граф | `getGraph`; фильтры `statuses`, `min_confidence`, `include_subtree` |
| Таймлайн | `listEvents` (фильтры по типу, источнику, сущности, окну, подстроке) |
| Карточка события | `getEvent` — сырой payload и `source_ref` в консоль источника |
| Карточка сущности | `getEntityCard` — `occurrences` по другим кейсам, `neighbors` по подтверждённым связям |
| Затянуть события | `attachEvents` — либо явные ссылки, либо выборка из источника |
| Список сущностей кейса | `listEntities` (фильтры `type_code`, `q`) — панель рядом с графом и пикер при рисовании связи |
| Завести индикатор руками | `createEntity` — хеш из бюллетеня до того, как появились события; идемпотентно по типу и ключу |
| Переименовать сущность | `updateEntity` — только `display_name` и `metadata`, идентичность не меняется |
| Вынести событие на граф | `createNode` — из таймлайна, чтобы от него можно было тянуть связи |
| Список узлов | `listNodes` — когда полный граф со всеми рёбрами не нужен |
| Нарисовать связь | `createEdge`; список допустимых `relation_code` — из `relation_types`, отфильтровать по `source_kind`/`target_kind` выбранных узлов |
| Очередь ревизии | `listEdges?statuses=proposed&origin=agent` на чтение, `reviewEdges` на батч |
| Разбор одной связи | `getEdge`, `updateEdge` (подтвердить или отклонить с причиной) |
| Провенанс связи | `listEdgeEvidence` — события целиком, у каждого `source_ref` в консоль источника |
| Довесить основания | `addEdgeEvidence` / `deleteEdgeEvidence` — доводы к связи обычно копятся, а не приходят разом |
| Убрать лишнее | `deleteNode`, `deleteEdge`, `deleteEntity`, `deleteEvent`, `deleteInvestigation` |
| Закрыть кейс | `updateInvestigation` со `status=closed` и `verdict` |

Удаление и отклонение — разные вещи, и путать их не стоит: `delete` для того,
что завели по ошибке, `reject` с причиной — для того, что проверили и
исключили. Второе идёт в отчёт, первое не оставляет следов. Поэтому же
`deleteEvent` откажет, если на событие ссылается подтверждённая связь, а
`deleteEdgeEvidence` — если это последнее основание подтверждённой связи.

Чего в контракте пока нет и о чём фронту стоит знать заранее:

- **Кто я и что мне можно.** Роли резолвятся на сервере и работают
  deny-by-default, но клиенту не отдаются. Пока рисуем всё и обрабатываем 403.
- **Тенант из тела не берётся.** `project_id` приходит в ответах, но не
  принимается в запросах — сервер выводит его из токена.
- **Реалтайма нет.** Граф и таймлайн обновляются перечиткой; после
  `reviewEdges` и `attachEvents` перезапросить `getGraph`.
- **Нереализованная ручка отвечает 501** с `code=not_implemented` — это не
  поломка, а «ещё не сделано»; можно прятать контрол.

## Принцип раскладки

Всё про ручку — в одном файле: её URL, операции и схемы запросов-ответов,
которые больше нигде не нужны. Схема уезжает в `shared/` только когда её
использует второй домен.

Отсюда и вид ссылок — по нему сразу видно область видимости:

```yaml
schema: { $ref: '#/components/schemas/EventPage' }         # своё, рядом в файле
schema: { $ref: '../shared/enums.yaml#/Severity' }         # общий словарь
'404': { $ref: '../shared/responses.yaml#/NotFound' }      # общий ответ
```

Описания в схемах — на английском. Они уезжают в сгенерированный Go, в `.d.ts`
и в Redoc, то есть читает их не только автор.

## Сборка

```bash
task spec       # собрать bundle.yaml из фрагментов и проверить
task spec-docs  # отрендерить документацию в api/docs.html
task gen        # всё сразу: спека, Go-контракт, заготовки ручек, TypeScript
```

Сборку и проверку делает [Redocly CLI](https://redocly.com/docs/cli):

```bash
redocly join openapi.yaml paths/*.yaml -o bundle.yaml --without-x-tag-groups
redocly lint bundle.yaml
```

Именно `join`, а не `bundle`: стандартный `$ref` подставляет один объект и не
умеет сливать карты, поэтому склеить несколько секций `paths` он не может.
`join` умеет и заодно ловит конфликты — одинаковый URL в двух файлах и
одноимённые схемы разных доменов (в собранном документе они схлопнулись бы
в одно пространство имён).

`bundle.yaml` и `build/` в репозитории не хранятся: это производное от `paths/`
и `shared/`. Нужен единый файл для Postman или сторонней кодогенерации —
собрать командой выше.

### Что важно знать про join

Команда помечена в Redocly как экспериментальная, и у неё есть особенности,
под которые подстроена раскладка:

- **`servers` и `security` нужны в каждом файле `paths/`.** Из шапки
  `openapi.yaml` они не подхватываются: `join` рассчитан на склейку разных API
  и корневые значения отбрасывает. Без дублирования спека объявила бы все ручки
  публичными без базового пути. Заодно это делает каждый файл пригодным для
  Swagger UI в одиночку.
- **`security` нормализуется на уровень операций.** В собранном документе
  корневого `security` не будет, вместо него требование появится в каждой
  операции — семантически то же самое.
- `--without-x-tag-groups` убирает автоматическую группировку тегов по
  файлам, которая нам не нужна: теги уже описаны в `openapi.yaml`.
- `info` берётся из первого аргумента, поэтому `openapi.yaml` идёт первым.
  Заголовки в доменных файлах — формальность для валидности фрагмента.

## Правила при добавлении ручки

1. URL и операции — в `paths/<домен>.yaml`, секция `paths`.
2. Схемы запроса и ответа — там же, в `components.schemas` этого файла.
3. Каждому полю — `description` на английском.
4. В `shared/` схема переезжает, только когда понадобилась второму домену.
5. Повторяющиеся параметры и ответы не инлайнить — брать из `shared/`.
6. `task gen` и коммит сгенерированного вместе со спекой. Что оно не разошлось,
   проверяет `task check-generated`: перегенерирует и падает на любом diff.

Новая ручка внутри существующего домена — это всё. Новый **домен** стоит трёх
дополнительных шагов, и их придётся сделать руками:

1. Файл начинается с шапки существующего: `openapi`, `info`, `servers`,
   `security`. Без `servers`/`security` ручки уедут в бандл без авторизации.
2. Тег — в `openapi.yaml`, иначе `lint` ругается на неописанный.
3. Пакет — в `API` и в `registerDomains` в
   `apps/investigations/internal/transport/router.go`. Забыть это компилятор
   не поможет: незарегистрированный домен молча отдаёт 404.

Два места, где легко наступить:

- запятая внутри `{ ... }` разделяет ключи, поэтому описание с запятой пишется
  блочно или в кавычках;
- `nullable: true` требует рядом `type` — при ссылке на словарь через `allOf`
  тип нужно указать явно, иначе `lint` ругается (правило `nullable-type-sibling`).

## Конвенции

- Auth: Bearer JWT платформы sb0rka; тенант резолвится по субъекту токена,
  из тела запроса не берётся.
- Ошибки: `{"error": {"code", "message", "details?"}}`; 400 — не смогли
  распарсить, 422 — распарсили и невалидно.
- Пагинация keyset: `?limit=&cursor=` → `{items, next_cursor}`;
  `next_cursor` отсутствует на последней странице.
- Мутации через `version` — оптимистичная блокировка, конфликт даёт 409
  со списком расхождений в `details`.
- Ничего не удаляется: reject вместо delete, отклонённое идёт в отчёт
  как «проверено и исключено».
